## 1. 범위

**포함 (Phase 1)**
- 시군구 단위로 아파트 매매 실거래 데이터를 월 단위로 수집하고 원본을 보관한다.
- 거래 건마다 이상거래 플래그를 붙이고, 그 사유를 기록한다.
- 단지·면적 그룹별로 정상 거래 기준 시세를 산출한다.
- 결과를 표 형식 리포트(CSV/엑셀)로 출력한다.

**제외 (Phase 2 이후 또는 범위 밖)**
- 층·향·동 보정, 회귀(헤도닉) 모델 → Phase 2
- 거래가 적은 단지를 인근 단지와 묶어 추정 → Phase 2
- 대시보드·API 형태의 결과물 → Phase 2
- 전월세, 분양권, 오피스텔 → 범위 밖
- 불법 여부 판단 → 범위 밖 (플래그는 통계적·형식적 특이 거래라는 뜻일 뿐이다)

### 3.2 데이터 수집 시 확인된 위험 (2026-10-26 점검)

카카오 PlayMCP의 AptInfo 래퍼로 강남구(11680) 2026년 9월 데이터를 조회해 보았다. 결과는 다음과 같다.
- **10건만 반환되었다.** 원천 API의 페이지 크기 기본값만큼만 받아 온 것으로 추정한다(미검증).
  수집 단계에서 `totalCount`와 실제 수신 건수를 반드시 대조해야 한다(FR-1).
- 거래유형·해제 여부·매도자·매수자 필드가 **없다.** 이 래퍼는 1차 원천으로 쓰지 않는다.
- 금액 표시 오류: 원값 82,500만원이 "8억 2천만원"으로 표시되었다. 금액은 항상 만원 단위 원값을 사용한다.

## 4. 기능 요구사항

**FR-1 수집**
- 입력: 시군구 코드(5자리), 계약년월 범위
- 모든 페이지를 수집하고, `totalCount`와 수신 건수가 다르면 실패로 처리한다.
- 원본 응답을 수집일과 함께 변경 없이 보관한다(스냅샷). 이후 단계는 이 스냅샷만 읽는다.

**FR-2 정제**
- `dealAmount`를 정수(만원)로, 계약일을 날짜로 변환한다.
- 그룹 키 = `aptSeq` + 면적 구간. `aptSeq`가 비어 있으면 (`umdNm`, `jibun`, `aptNm`)으로 대체하고, 대체했다는 표시를 남긴다.
- 원천의 같은 거래가 중복으로 들어오면 제거한다. 중복 기준은 plan.md에서 정한다.

**FR-3 플래그 부여** (한 거래에 여러 플래그가 붙을 수 있다)

| 코드 | 플래그 | 조건 | 기준 시세 산출 |
|---|---|---|---|
| F1 | 해제 | 해제 여부 필드가 해제를 표시 | 제외 |
| F2 | 직거래 | 거래유형 = 직거래 | 제외 (설정으로 포함 가능) |
| F3 | 통계적 이상치 | §5 규칙 | 제외 |
| F4 | 판정 보류 | 비교 창 안의 정상 거래가 최소 건수 미만 | 해당 없음 |
| F5 | 법인 관련 | 매도자 또는 매수자 구분이 법인 | 포함 (참고 표시만) |
| F6 | 미확정 | 계약일이 미확정 기간 안에 있음 | 포함하되 결과에 표시 |

**FR-4 기준 시세 산출**
- 그룹별·월별로, 비교 창 안의 정상 거래를 대상으로 중위가와 거래 건수를 산출한다.
- 정상 거래가 최소 건수 미만이면 값을 내지 않고 '산출 불가'로 표시한다. 인근 단지 값을 빌려 오지 않는다(Phase 2).

**FR-5 출력**
- 거래 단위 표: 원천 필드 + 플래그 목록 + 플래그 사유 + 그룹 중위가 대비 괴리율
- 그룹 단위 표: 기준 시세, 정상/전체 거래 건수, 플래그별 건수, 미확정 여부
- 실행 메타데이터: 스냅샷 수집일, 설정값 전체, 실행 일시

## 5. 통계적 이상치 규칙 (F3)

intent의 Q1(±N% 방식인가, 회귀 방식인가)에 대해 **Phase 1은 중위수·MAD 방식**을 제안한다.

- 대상 거래 가격 `p`를 그룹 내 비교 창의 정상 거래(F1·F2 제외)와 비교한다.
- `x = ln(p)`, `m = median(ln(비교 거래))`, `MAD = median(|ln(비교 거래) − m|)`
- `|x − m| > k × 1.4826 × MAD`이면 F3로 판정한다.
- MAD = 0이면(비교 거래 가격이 모두 같으면) ±N% 규칙으로 대체한다: `|p / e^m − 1| > N`

**이렇게 제안하는 이유**
- 평균·표준편차와 달리, 이상치가 섞여 있어도 기준값이 끌려가지 않는다.
- 로그 가격을 써서 가격대가 달라도 같은 상대 기준을 적용한다.
- 회귀 방식은 층·향 데이터와 표본 수가 필요하다(Q2, Phase 2).

**한계**
- 상승장이나 하락장에서는 비교 창이 과거 가격이라 정상 거래도 이상치로 판정될 수 있다(추세 편향).
  비교 창을 짧게 잡거나, Phase 2에서 지역 가격지수로 보정한다.
- 비교 창이 직전 거래만 보므로, 신고 시차 때문에 최근 거래가 늦게 반영되면 결과가 바뀔 수 있다(F6로 표시).

## 6. 설정값 (제안값: 승인 전 결정 필요)

| 설정 | 제안값 | 근거 | intent 질문 |
|---|---|---|---|
| 비교 창 N개월 | 6 | 3개월은 표본이 부족하고 12개월은 추세 편향이 크다는 절충 (검증 필요) | Q6 |

| N (MAD=0 대체) | 0.15 (±15%) | 임의 초기값. 표본 검증으로 조정 | Q1 |
| 직거래 처리 | 기준 시세에서 제외, 플래그 유지 | 가중치는 근거 데이터가 없어 임의값이 됨 | Q3 |
| 미확정 기간 | 2개월 | 신고 30일 + 해제 신고 30일 | — |

설정값은 파일 하나로 관리하고 버전을 기록한다. 결과의 실행 메타데이터에 사용한 값을 그대로 남긴다.

## 7. 비기능 요구사항

- **재현성:** 같은 스냅샷과 같은 설정이면 같은 결과가 나와야 한다. 결과에 무작위 요소를 쓰지 않는다.
- **API 한도:** data.go.kr 계정의 일일 호출 한도 안에서 동작해야 한다. 한도 수치는 계정에서 확인한다(미확인).
  이미 받은 월의 데이터는 다시 호출하지 않는다. 단, 미확정 기간의 월은 다시 받는다.
- **개인정보:** 공개 데이터만 사용한다. 개인 식별 정보를 다른 데이터와 결합하지 않는다.
- **표현 원칙:** 결과물에 '불법', '허위', '작전' 같은 단어를 쓰지 않는다. F3는 "통계적 이상치"로만 표기한다.

## 8. 검증 계획

1. **기준선 실측:** 지금 하는 수작업 방식으로 단지 3곳을 분석해 실제 소요 시간을 잰다(intent의 30분은 추정치).
2. **수집 검증:** 시군구 3곳 × 3개월에서 `totalCount`와 수신 건수가 일치하는지 확인하고, 국토부 실거래가 공개시스템 화면과 표본을 대조한다.
3. **필드 검증:** 기술문서로 `dealingGbn`, `cdealType`, `slerGbn`, `buyerGbn`의 코드값을 확인하고, 결측률을 측정한다.
4. **플래그 품질:** F3 판정 거래 50건과 비판정 거래 50건(총 100건)을 수기로 검토해 정밀도와 놓친 건 수를 기록한다.
   표본은 단지 규모·가격대별로 층화해 뽑는다. 강남 고가 단지만 보면 결과가 치우친다.
5. **재현성:** 같은 스냅샷으로 두 번 실행해 결과가 바이트 단위로 같은지 확인한다.
