# 단계별 질문 뱅크 (복사해서 사용)

규칙: 한 턴 3~5문항 / 총 25문항 상한 / 모든 문항에 기본값과 "그 외·모르겠다" 포함.

## S1 문제·사용자
1. 이 기능이 없는 지금은 어떻게 처리하고 있습니까? (현행 대체 수단)
2. 1차 타깃 사용자 1명을 지목한다면? (a 본인 / b 팀 내부 / c 외부 고객 / d 미정)
3. 사용 빈도: (a 상시 / b 주 / c 월 / d 1회성)
4. 이 기능이 오작동하면 피해 수준은? (a 치명적 / b 불편 / c 무관)

## S2 성공 기준
5. 성공을 숫자로 표현하면? (없으면 "없음")
6. 그 숫자의 현재 기준선은? (없으면 "기준선 없음" — 추정 금지)
7. 어떤 신호가 보이면 중단합니까? (Kill Switch)
8. 측정 데이터 출처: (a 로그 / b 수기 / c 외부 API / d 측정 불가)

## S3 범위
9. 이번 버전 필수 3가지는?
10. 이번엔 빼도 되는 것은?
11. 명시적으로 하지 않을 것(Non-goal) 3가지는?
12. 마감이 있습니까? 그 날짜가 고정된 이유는?

## S4 유스케이스
13. 대표 시나리오를 사용자 관점 3~7단계로.
14. 입력과 출력, 출력 형식은? (화면 / 파일 / API)
15. 잘못된 입력 시 기대 동작은?
16. 동시 사용자 상황이 있습니까?

## S5 데이터·기술 (도메인 누락 방지 — 생략 금지)
17. 데이터 출처: 공식 API / 크롤링 / 수기 / 내부 DB?
18. 갱신 주기와 시차(lag)는?
19. 호출 한도·요금·약관 제약과 초과 시 동작은?
20. 개인정보·민감정보 포함 여부는?
21. 결측·오류 데이터의 화면 표기 규칙은? (0 표기 금지 / "확인 불가" 표기 등)
22. 실행 환경: 로컬 / 서버 / 오프라인 / 브라우저?

## S6 리스크
23. 이 계획이 틀린다면 가장 큰 이유는?
24. 사용자가 안 쓴다면 그 이유는?
25. 데이터 원천이 끊기면 무엇을 합니까?

## 진행 중 상시 질문 (사용자에게 하지 말고 작성자가 자문)
- 이 질문의 답이 바뀌면 설계나 일정이 달라지는가? 아니면 삭제하고 기본값 + `[추정]` 처리.
- 지금 늘어난 이 기능은 원래 문제 정의에서 나온 것인가? 아니면 v2 백로그로.
